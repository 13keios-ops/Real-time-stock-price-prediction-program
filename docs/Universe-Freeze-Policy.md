# Universe Freeze Policy

## 1. 목적

이 문서는 종목 유니버스를 어떻게 산출하고, 언제 바꾸고, 월중에는 어떻게 고정할지 정의합니다.

이 정책이 중요한 이유:

1. live와 backtest에서 같은 종목군을 써야 합니다.
2. 월중에 종목군이 흔들리면 성능 비교가 어렵습니다.
3. 유동성이 높은 종목군을 유지하면서도 과도한 turnover를 피해야 합니다.

## 2. 현재 기본 유니버스

- `최근 60거래일 중앙값 거래대금 상위 30종목`
- 대상 시장: `KOSPI + KOSDAQ`
- 제외: `ETF`, `ETN`, `스팩`, `우선주`, `관리종목`, `거래정지 종목`

## 3. 핵심 개념

### Selection Date

- 어떤 데이터를 기준으로 종목을 뽑는 날짜

### Effective Period

- 뽑은 종목군을 실제로 사용하는 기간

### Freeze

- effective period 동안 종목군 구성을 유지하는 원칙

## 4. 현재 작업 기준안

### Selection Date

- 매월 마지막 거래일

### Lookback Window

- selection date를 포함한 최근 `60거래일`

### Effective Period

- 다음 달 첫 거래일 ~ 다음 달 마지막 거래일

### Universe Freeze

- 한 번 확정된 월간 유니버스는 해당 월 동안 유지

## 5. 월중 처리 정책

기본 원칙:

- `유니버스 편입`은 월중에 바꾸지 않음
- `거래 가능 여부`는 월중에 별도로 바뀔 수 있음

즉:

- 유니버스는 frozen
- tradability는 dynamic

## 6. 긴급 예외 규칙

아래 경우는 유니버스 자체를 바꾸기보다 `거래 제외`로 처리합니다.

1. 거래정지
2. 상장폐지 절차
3. 기업행위로 인한 가격 불연속
4. 데이터 매핑 실패

## 7. 산출 규칙 세부

### 기본 산출 지표

- 일별 거래대금

### 기본 집계 방식

- 최근 60거래일의 `중앙값`

중앙값을 쓰는 이유:

1. 하루 급등 테마주 왜곡이 줄어듭니다.
2. 지속적인 유동성을 더 잘 반영합니다.

## 8. 동률 및 경계 처리

초기 기준:

1. 거래대금 중앙값 우선
2. 최근 20거래일 중앙값 거래대금 보조
3. 그래도 같으면 시가총액 또는 종목코드 순 고정

## 9. 버전 관리 정책

예시:

- `univ_top_value_30_2026_04`
- `univ_top_value_30_2026_05`

각 버전에는 최소 아래가 필요합니다.

1. selection date
2. effective_from
3. effective_to
4. selection query version
5. 포함 종목 목록

## 10. 학습과 운영의 일관성

- 특정 시점 샘플은 당시 effective universe 기준으로 해석
- 미래 시점 종목 편입 정보를 과거 학습에 넣지 않음

## 11. 현재 권장 구현 방식

### Universe Version

- 월간 구성 자체

### Trading Eligibility Overlay

- 장중 거래 가능 여부

## 12. 현재 작업 기준안 요약

1. 매월 마지막 거래일 기준 산출
2. 최근 60거래일 거래대금 중앙값 사용
3. 다음 달 전체에 frozen 적용
4. 월중 편입 변경 없음
5. 거래 가능 여부는 overlay로 따로 관리
