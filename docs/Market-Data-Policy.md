# Market Data Policy

## 1. 목적

이 문서는 가격, 호가, 분봉, 기업행위 데이터를 어떻게 해석하고 저장할지 정의합니다.

핵심 이유:

1. 같은 주가 데이터라도 `raw`와 `adjusted`에 따라 결과가 달라집니다.
2. 분봉 생성 규칙이 다르면 백테스트와 live가 어긋납니다.
3. 데이터 품질 문제를 명확한 규칙으로 처리해야 자동 모의주문이 안전합니다.

## 2. 기본 원칙

1. 실행과 모의주문 평가는 `raw executable price`를 기준으로 합니다.
2. 원본 이벤트는 수정 없이 보관합니다.
3. 가공 데이터는 정책을 명시한 뒤 생성합니다.
4. 이벤트 시각과 수신 시각을 분리 저장합니다.

## 3. Raw vs Adjusted 정책

### Raw 가격

사용처:

- 실시간 예측
- 모의주문 체결 계산
- 손익 계산
- replay 검증

### Adjusted 가격

사용처:

- 장기 히스토리 연구
- 일부 학습 특징 검토

### 현재 기준안

- `실행/평가 = raw`
- `장기 연구용 추가 특징 = 필요 시 adjusted`

## 4. 이벤트 시각 정책

모든 시장 데이터는 최소 아래 두 시각을 구분합니다.

- `event_time`
- `received_at`

정책:

- 정렬과 라벨 생성은 기본적으로 `event_time`
- 운영 품질 점검은 `received_at - event_time`

## 5. 분봉 생성 정책

초기 기준은 `1분 바`입니다.

### 1분 바 생성 규칙

1. 한국 시장 분 경계 기준으로 생성
2. 해당 분에 체결이 있으면 실제 체결값으로 바 생성
3. 해당 분에 체결이 없으면 직전 종가를 이어받고 `volume=0`, `trade_count=0`
4. `has_trade` 플래그를 함께 저장하는 것이 좋음

## 6. 호가 데이터 정책

- 원본 호가 이벤트는 `raw.orderbook_ticks`
- 실시간 계산용 요약은 `curated.orderbook_snapshots`
- 특정 시점의 최신 유효 호가를 사용

호가가 너무 오래 갱신되지 않으면 신규 주문을 금지합니다.

## 7. 소스 우선순위 정책

1. `KIS WebSocket`
2. `KIS REST`
3. `KRX / 기타 참조 소스`

실시간 거래 판단은 한국투자 시세 기준으로 합니다.

## 8. 기업행위 정책

별도 관리 대상:

- 액면분할
- 거래정지/재개
- 권리락
- 관리종목 전환
- 종목코드 변경

현재 기준안:

1. 기업행위는 별도 이벤트 테이블로 저장
2. 해당 구간은 특징 생성 시 flag 추가 또는 샘플 제외 검토
3. 장기 학습 시 adjusted 여부를 명시

## 9. 데이터 품질 게이트

모의주문 전에 최소 아래를 통과해야 합니다.

1. 최신 체결 시각이 허용 범위 내
2. 최신 호가 시각이 허용 범위 내
3. 필수 특징이 결측이 아님
4. 장 상태가 거래 가능

## 10. 현재 작업 기준안

- raw 이벤트는 항상 원본 보관
- 분봉은 1분 기준
- 빈 분은 직전 종가 carry-forward + zero volume
- 전략 손익과 주문 검증은 raw 기준
- 기업행위는 별도 이벤트로 저장
