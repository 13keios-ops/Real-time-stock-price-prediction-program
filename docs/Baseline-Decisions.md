# Baseline Decisions

## 결정 일시

- 2026-04-10
- 2026-04-11 운영 기준 추가 확정

## 목적

이 문서는 현재 프로젝트에서 더 이상 아이디어 단계로 두지 않고, `개발 착수 전 기준선`으로 확정한 항목을 정리합니다.

핵심 원칙:

- 과도하게 넓지 않은 범위에서 시작한다.
- 실시간 수집이 가능한 데이터만 우선 사용한다.
- 정확도 개선 여부를 실험으로 검증할 수 있게 정의한다.

## 1. 초기 종목 유니버스

### 확정안

- `최근 60거래일 중앙값 거래대금 상위 30종목`
- 시장 범위는 `KOSPI + KOSDAQ`
- `월 1회` 리밸런싱

### 제외 규칙

- ETF
- ETN
- 스팩
- 우선주
- 관리종목
- 거래정지 종목

### 선택 이유

1. 거래량보다 거래대금이 실제 유동성과 체결 가능성을 더 잘 반영합니다.
2. 최근 하루 급등 종목이 아니라, 지속적으로 활발한 종목군을 잡을 수 있습니다.
3. 30종목은 초기 실시간 수집과 모델링 범위로 부담이 적고, 품질 관리가 쉽습니다.

## 2. 예측 수평선

### 확정안

- `15분 방향 분류`
- `60분 방향 분류`

### 의미

- `15분 방향 분류`: 지금 시점 기준 향후 15분 수익률 방향을 예측
- `60분 방향 분류`: 지금 시점 기준 향후 60분 수익률 방향을 예측

### 선택 이유

1. 1~5분 수준은 노이즈가 커서 초기에 불안정합니다.
2. 당일 종가 예측은 장중 이벤트와 시간대 효과가 복잡해 초기 검증이 어렵습니다.
3. 15분과 60분은 단기 모멘텀과 이벤트 반응을 함께 보기 좋은 균형점입니다.

## 3. 실시간 시세 API 공급자

### 1순위 확정안

- `한국투자 Open API`

### 보조 소스

- `KRX OPEN API`: 종목 기준정보, 거래대금/통계성 데이터, 검증용
- `OpenDART`: 공시
- `NAVER 검색 API`: 뉴스/카페글 등 반응 프록시
- `NAVER DataLab`: 검색량 관심도

### 보류 후보

- `키움 REST API`

### 선택 이유

1. 국내주식 REST/WebSocket 기반 개발 흐름에 적합합니다.
2. 실시간 시세/호가/기본시세 중심의 연구용 시작점으로 무난합니다.
3. 비용 효율성과 구현 난이도를 함께 고려했을 때 1차 선택지로 적절합니다.

## 4. 초기 라벨 임계값

### 확정안

- `15분`: `+0.35% 이상 = 상승`, `-0.35% 이하 = 하락`, 그 사이는 `중립`
- `60분`: `+0.8% 이상 = 상승`, `-0.8% 이하 = 하락`, 그 사이는 `중립`

### 선택 이유

1. 너무 작은 변동까지 맞추려 하면 노이즈를 학습하기 쉽습니다.
2. 거래비용과 슬리피지를 고려하면 의미 있는 움직임에 집중하는 편이 낫습니다.
3. 초기에는 단순한 고정 임계값이 실험과 해석에 유리합니다.

## 5. 거래비용/슬리피지 기준

### 확정안

- `기본형`을 메인 검증 시나리오로 사용
- 동시에 `낙관형`, `보수형` 시나리오를 함께 계산

### 의미

- 기본 성과는 현실적인 비용 가정으로 본다.
- 추가로 더 좋은 조건과 더 나쁜 조건에서도 전략이 버티는지 같이 본다.

### 선택 이유

1. 비용과 슬리피지에 따라 전략 성과가 과대평가될 수 있습니다.
2. 단일 가정만 보면 실전 전환 시 리스크를 놓치기 쉽습니다.
3. 기본형 + 비교 시나리오 구조가 가장 균형적입니다.

## 6. 모의주문 규칙 기준

### 확정안

- `기본형 진입/청산 규칙` 사용
- 강한 상승 신호만 선별
- 손절/익절/최대 보유시간을 함께 운영

### 의미

- 지나치게 많은 거래를 만들지 않고
- 너무 엄격해서 검증 데이터가 부족해지지도 않는 균형형 전략입니다.

### 선택 이유

1. 초기 검증 단계에서는 거래 수와 품질의 균형이 중요합니다.
2. 공격형은 노이즈 거래가 많고, 보수형은 데이터가 너무 늦게 쌓일 수 있습니다.
3. 기본형이 가장 빠르게 튜닝 포인트를 찾기 좋습니다.

## 7. 장중 주문 시간대 규칙

### 확정안

- `개장 직후 10~15분` 신규 진입 금지
- 장중 중간 시간대는 정상 허용
- `장 마감 전 20~30분` 신규 진입 금지
- 마감 전에는 보유 포지션 정리 중심

### 선택 이유

1. 개장 직후와 마감 직전은 노이즈와 변동성이 큽니다.
2. 장중 중간 시간대가 신호 품질을 검증하기 가장 안정적입니다.
3. 자동 모의주문 단계에서는 극단적 시간대를 피하는 편이 안전합니다.

## 8. 계좌 안전장치 기준

### 확정안

- `paper/live` 설정 분리
- 기본 실행 모드는 항상 `paper`
- 실전 주문은 기본값 `disabled`
- 실전 API는 당분간 조회/준비용으로만 사용

### 선택 이유

1. 사용자 계좌 보호가 성능보다 우선입니다.
2. 실전 API 보유와 실전 주문 허용은 전혀 다른 문제입니다.
3. 개발 초기에는 오주문 가능성을 원천 차단하는 것이 맞습니다.

## 9. 다음 실험에서 비교할 대안

초기 구현 이후 아래 대안과 비교합니다.

### 종목군 대안

- 상위 50종목 확장안
- 코어 30종목 + 당일 거래대금 급증 종목 추가안

### 라벨 대안

- `15분 ±0.5%`, `60분 ±1.2%`의 보수적 임계값
- 최근 변동성 기반 가변 임계값

### API 대안

- 키움 REST API를 보조 또는 대체 후보로 재검토

## 10. 이 기준으로 얻는 장점

1. 실시간 수집 범위가 과도하게 커지지 않습니다.
2. 예측 문제 정의가 명확해집니다.
3. 정확도 개선 실험을 반복 가능하게 설계할 수 있습니다.
4. 개발 착수 시 데이터 스키마와 평가 파이프라인을 바로 정할 수 있습니다.

## 11. 아직 열어둔 항목

- 텍스트 원문을 어디까지 수집할지
- 연구용 UI를 어떤 형태로 시작할지
- 종목군 리밸런싱 자동화를 언제 도입할지
- 고정 임계값에서 변동성 연동 임계값으로 넘어갈 시점
