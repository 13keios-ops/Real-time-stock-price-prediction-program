# Realtime Operations Plan

## 1. 운영 목표

이 시스템의 핵심은 단순한 모델 학습이 아니라 `실시간으로 안정적으로 데이터를 받고, 최신 상태로 예측을 갱신하는 것`입니다.

따라서 운영 설계는 다음 세 가지를 동시에 만족해야 합니다.

1. 데이터가 제때 들어와야 합니다.
2. 모델 입력 특징이 최신 상태여야 합니다.
3. 장애가 생겨도 예측 시스템이 완전히 멈추지 않아야 합니다.

## 2. 실시간 파이프라인 흐름

### 시세/호가

- WebSocket 연결 유지
- 재연결 로직 준비
- 이벤트 발생 시 즉시 raw 저장
- 1분/5분/15분 단위 요약 특징 갱신

### 공시/뉴스/검색

- 주기적 폴링
- 마지막 수집 시점 기준 증분 수집
- 게시 시각 기준 정렬
- 종목 매핑 및 키워드 매핑 수행

### 특징 갱신

- 최신 가격 특징 갱신
- 최신 이벤트 특징 갱신
- 종목별 최신 상태 스냅샷 생성

### 추론

- 종목별 최신 특징 로드
- 예측 점수 계산
- 신뢰도 및 설명 특징 추출
- 저장 및 경보 발행

## 3. 운영 모드 구분

### 장전

- 전일 데이터 정리
- 공시/뉴스 초기 적재
- 모델 상태 점검
- API 인증 상태 점검

### 장중

- 실시간 수집
- 특징 실시간 갱신
- 예측 주기 실행
- 경보와 로그 누적

### 장후

- 일일 데이터 정합성 점검
- 예측 대비 실제 성과 계산
- 에러 및 누락 점검
- 재학습 후보 데이터 확정

## 4. 장애 시나리오와 대응

| 장애 | 영향 | 대응 |
| --- | --- | --- |
| WebSocket 끊김 | 시세 공백 발생 | 자동 재연결, 마지막 수신 시각 경보 |
| API 호출 한도 초과 | 뉴스/검색 지연 | 폴링 주기 완화, 우선순위 종목만 수집 |
| 종목 매핑 실패 | 이벤트가 잘못 연결됨 | 수동 검수 큐, 매핑 룰 로그 저장 |
| DB 지연 | 특징 계산 지연 | 비동기 큐 버퍼, 최근 캐시 사용 |
| 모델 추론 실패 | 점수 미생성 | 직전 안정 모델 fallback |

## 5. 실시간 운영에서 가장 중요한 지표

### 데이터 지표

- 이벤트 수신 지연
- 종목별 결측 비율
- API 성공률
- 소스별 최신 수집 시각

### 시스템 지표

- 큐 적체량
- 특징 계산 지연
- 추론 지연
- 저장 실패 건수

### 모델 지표

- 최근 예측 수 대비 hit rate
- 구간별 calibration
- 종목군별 성능 편차
- 이벤트 유형별 성공/실패 패턴

## 6. 재학습 운영 전략

처음부터 온라인 러닝을 도입하기보다, `짧은 주기의 반복 재학습`이 현실적입니다.

### 초기 권장안

- 매 영업일 장후 데이터 확정
- 주 1회 또는 필요 시 재학습
- 챔피언 모델과 챌린저 모델 병행 비교

### 이후 확장안

- 최근 장세 가중치 확대
- 테마 장세와 일반 장세 분리 학습
- 종목군별 모델 또는 장세별 모델 분리

## 7. 설명 가능한 운영 로그

각 예측에 대해 최소한 아래 정보는 반드시 남기는 것이 좋습니다.

- 예측 시각
- 종목
- 모델 버전
- 특징 버전
- 점수와 클래스
- 상위 근거 특징
- 실제 결과
- 사후 평가 결과

## 8. 운영 설계 원칙

1. 예측 정확도만큼 데이터 신뢰도를 중시합니다.
2. 실시간 추론보다 데이터 누수 방지가 더 중요합니다.
3. 모델 실패 시에도 데이터 수집은 계속되어야 합니다.
4. 새 모델은 기존 모델과 비교 검증 후 교체합니다.
