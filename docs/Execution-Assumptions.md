# Execution Assumptions

## 1. 목적

모의투자 검증은 단순히 예측이 맞았는지만 보면 부족합니다. 실제 체결과 비용을 어느 정도 반영해야 전략이 과대평가되지 않습니다.

이 문서는 초기 모의투자에서 사용할 `체결`, `슬리피지`, `거래비용` 가정을 정의합니다.

## 2. 기본 원칙

1. 실제보다 낙관적인 체결을 가정하지 않습니다.
2. 비용 항목은 코드 상수로 박지 말고 설정값으로 둡니다.
3. 종목 유동성에 따라 슬리피지를 다르게 줄 수 있게 설계합니다.

### 현재 확정 선택안

- 메인 평가는 `기본형` 시나리오로 진행
- 동시에 `낙관형`, `보수형` 결과를 함께 비교

## 3. 초기 체결 가정

### 시장가성 매수

- 기준 가격: `best_ask`
- 모의 체결 가격: `best_ask + slippage`

### 시장가성 매도

- 기준 가격: `best_bid`
- 모의 체결 가격: `best_bid - slippage`

### 지정가 주문

- 지정가가 체결 가능 범위에 들어오면 체결
- 그렇지 않으면 미체결 유지 또는 취소

초기 버전에서는 복잡한 부분 체결 모델보다 단순한 전체 체결 가정으로 시작합니다.

## 4. 초기 슬리피지 모델 제안

슬리피지는 현재 사실값이 아니라 `보수적 검증용 가정`으로 둡니다.

### 기본안

- `slippage = max(1틱, 체결 기준가의 0.05%)`

### 보수안

- `slippage = max(1틱, 체결 기준가의 0.10%)`

초기 연구 단계에서는 `기본안`과 `보수안`을 함께 비교하는 것이 좋습니다.

현재는 `기본안`을 메인 시나리오로 채택합니다.

## 5. 거래비용 가정

거래비용은 브로커/시장 규칙에 따라 바뀔 수 있으므로 하드코딩하지 않습니다.

코드에서 별도 설정값으로 둬야 할 항목:

- `commission_buy_bps`
- `commission_sell_bps`
- `sell_side_tax_bps`
- `other_fees_bps`

### 초기 권장 방식

- 1차 구현: 비용 항목을 파라미터화
- 2차 검증: 실제 계좌 조건에 맞춰 설정값 반영
- 3차 비교: 낙관/기본/보수 시나리오 동시 평가

## 6. 체결 불가 조건

아래 경우에는 모의주문을 체결시키지 않거나 차단합니다.

1. 데이터가 오래됨
2. 호가 정보 없음
3. 스프레드가 비정상적으로 큼
4. 유동성이 급감함
5. 주문 수량이 너무 큼

## 7. 주문 수량 가정

초기에는 `포지션 금액 기준 -> 정수 주식 수량 환산` 방식이 적합합니다.

예시:

1. 총 자산의 5%를 목표 금액으로 설정
2. 현재 추정 체결가로 나눠 수량 계산
3. 최소 거래 단위에 맞춰 내림

## 8. 검증 시나리오

전략 평가는 최소 세 가지 비용 시나리오로 보는 것이 좋습니다.

### 낙관 시나리오

- 낮은 수수료
- 낮은 슬리피지

### 기본 시나리오

- 실제 예상에 가까운 비용

### 보수 시나리오

- 더 큰 슬리피지
- 더 높은 부대비용

이렇게 해야 전략이 특정 가정에서만 좋아 보이는지 확인할 수 있습니다.

## 9. 성능 해석 원칙

같은 모델이라도 아래 차이로 성과가 달라질 수 있습니다.

1. 예측은 좋아도 체결 가정이 나쁘면 손익이 악화됩니다.
2. 예측은 평범해도 주문 필터가 좋으면 성과가 좋아질 수 있습니다.
3. 슬리피지에 취약한 전략은 실전 전환 가치가 낮습니다.

## 10. 초기 구현 체크리스트

1. 체결 가격 계산 함수 분리
2. 슬리피지 모델 설정값화
3. 수수료/세금 설정값화
4. 비용 반영 전후 손익 모두 기록
5. 낙관/기본/보수 시나리오 비교 기능 준비
