# Dashboard Plan

## 1. 목적

초기 화면은 화려한 투자 서비스가 아니라 `연구용 운영 대시보드`여야 합니다.

즉, 사용자가 한 화면에서 아래를 빠르게 파악할 수 있어야 합니다.

1. 지금 어떤 종목이 강한 신호를 보이는가
2. 그 신호는 가격 때문인가, 이벤트 때문인가, 심리 프록시 때문인가
3. 데이터 수집과 예측 시스템은 정상인가

## 2. 핵심 화면 구성

초기 버전은 아래 4개 화면으로 충분합니다.

### 화면 A. 시장 개요

목적:

- 전체 유니버스 중 어떤 종목이 현재 강한 신호를 갖는지 한눈에 파악

핵심 위젯:

- 종목 랭킹 테이블
- 15분 예측 상위 종목
- 60분 예측 상위 종목
- 최근 거래대금 급증 종목
- 최근 뉴스/공시 발생 종목
- 시스템 상태 요약

종목 랭킹 테이블 컬럼 예시:

- 종목명
- 현재가
- 등락률
- 거래대금
- 15분 예측 클래스
- 15분 신뢰도
- 60분 예측 클래스
- 60분 신뢰도
- 최근 이벤트 수

### 화면 B. 종목 상세

목적:

- 특정 종목의 최근 가격 흐름, 이벤트, 예측 근거를 상세 확인

핵심 위젯:

- 분봉 차트
- 거래량 차트
- 호가 불균형 추이
- 최근 이벤트 타임라인
- 현재 예측 카드
- 상위 영향 요인
- 과거 예측 vs 실제 결과

예측 카드에 표시할 내용:

- 예측 시각
- 15분 방향
- 60분 방향
- 신뢰도
- 상위 3개 근거

### 화면 C. 이벤트 모니터

목적:

- 공시, 뉴스, 검색 급증 같은 이벤트성 자극을 별도로 추적

핵심 위젯:

- 최신 공시 피드
- 최신 뉴스 피드
- 검색량 급증 종목
- 이벤트 유형별 필터
- 이벤트 이후 예측 변화량

### 화면 D. 운영 상태

목적:

- 수집 지연, API 장애, 예측 실패를 빠르게 발견

핵심 위젯:

- 소스별 마지막 수집 시각
- WebSocket 연결 상태
- API 성공률
- 종목별 결측률
- 최근 예측 생성 수
- 최근 오류 로그 요약

## 3. 화면 우선순위

1차 개발에서는 모든 화면을 다 만들 필요가 없습니다.

### 1차 필수

- 시장 개요
- 종목 상세
- 운영 상태

### 2차 확장

- 이벤트 모니터
- 예측 성과 분석 전용 화면

## 4. 사용자 흐름

초기 사용 흐름은 단순해야 합니다.

1. 시장 개요에서 신호 강한 종목 확인
2. 종목 상세로 이동
3. 최근 이벤트와 예측 근거 확인
4. 사후에 예측 성과 분석

## 5. 경보 기준 예시

초기 경보는 아래 정도로 시작하는 것이 좋습니다.

### 예측 경보

- 15분 상방 확률 상위 종목
- 60분 하방 확률 상위 종목
- 신뢰도 임계값 초과 종목

### 이벤트 경보

- 공시 발생
- 뉴스 급증
- 검색량 급증
- 거래대금 급증

### 운영 경보

- WebSocket 끊김
- 특정 소스 수집 지연
- 예측 생성 실패

## 6. 시각화 권장안

초기에는 이해하기 쉬운 형태를 우선합니다.

- 가격: 캔들 또는 라인 차트
- 거래량: 막대 차트
- 확률/신뢰도: 수평 바 또는 배지
- 이벤트: 타임라인
- 운영 상태: 상태 카드

## 7. 초기 UI 기술 선택

개발 착수 시점에는 아래 둘 중 하나가 현실적입니다.

### 옵션 A. Streamlit

- 장점: 연구용 화면을 매우 빠르게 만들 수 있음
- 단점: 운영 UI로 커질수록 한계가 있음

### 옵션 B. FastAPI + 경량 프론트엔드

- 장점: 이후 확장성 좋음
- 단점: 초기 속도는 느릴 수 있음

현재 프로젝트 단계에서는 `Streamlit 또는 매우 얇은 웹 UI`로 시작하는 것이 적합합니다.

## 8. 나중에 추가할 수 있는 기능

- 유사 패턴 과거 사례 비교
- 예측 근거 SHAP 시각화
- 테마군 묶음 분석
- 장중 리플레이
- 알림 히스토리 조회
