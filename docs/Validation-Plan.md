# Validation And Accuracy Improvement Plan

## 1. 왜 이 문서가 중요한가

이 프로젝트에서 "정확도가 좋아졌다"는 말은 감으로 판단하면 안 됩니다. 같은 데이터 누수나 특정 장세 편향이 있으면 겉보기 성능은 쉽게 좋아질 수 있기 때문입니다.

따라서 정확도 향상은 반드시 `라벨 정의`, `평가 기준`, `운영 중 모니터링`이 함께 있어야 합니다.

## 2. 우선 평가할 예측 과제

### 과제 A. 15분 방향 분류

- 입력 시점 이후 15분 수익률 기준
- 상방, 하방, 중립으로 분류

### 과제 B. 60분 방향 분류

- 입력 시점 이후 60분 수익률 기준
- 상방, 하방, 중립으로 분류

### 과제 C. 이벤트 직후 변동성 확대 탐지

- 공시/뉴스 이후 일정 시간 내 변동성 확대 가능성 분류

## 3. 라벨 설계 원칙

1. 너무 작은 가격 움직임까지 억지로 맞추려 하지 않습니다.
2. 거래비용을 고려한 임계값을 둡니다.
3. 장마감에 가까운 구간은 별도 규칙을 둡니다.
4. 예측 시점 이후 정보가 라벨 생성 과정에 새어 들어가지 않도록 합니다.

예시:

- 15분 후 수익률이 `+0.4%` 이상이면 상방
- `-0.4%` 이하이면 하방
- 그 사이는 중립

임계값은 종목군 변동성과 거래비용을 반영해 나중에 조정합니다.

## 4. 오프라인 평가 기준

### 기본 분류 지표

- balanced accuracy
- precision / recall
- F1
- PR-AUC

### 확률 품질 지표

- Brier score
- calibration error
- 구간별 예측 확률 대비 실제 적중률

### 투자 관점 지표

- 상위 점수 신호의 적중률
- 거래비용 반영 기대값
- 최대 낙폭
- 회전율

## 5. 데이터 분할 방식

일반적인 랜덤 분할은 사용하지 않는 것이 좋습니다.

권장 방식:

- 시간 순서 기반 학습/검증/테스트 분리
- 워크포워드 검증
- 장세 구간별 홀드아웃 검증

예시:

1. 과거 N개월 학습
2. 다음 1개월 검증
3. 그 다음 1개월 테스트
4. 창을 앞으로 이동하며 반복

## 6. 비교해야 하는 베이스라인

새 모델을 평가할 때는 아래와 최소 비교해야 합니다.

1. 랜덤 분류기
2. 직전 수익률 기반 단순 모멘텀
3. 거래량 급증 기반 규칙 모델
4. 가격/거래량만 쓰는 트리 모델

## 7. 정확도 향상 루프

정확도는 아래 루프로 개선합니다.

### Step 1. 데이터 품질 점검

- 누락, 지연, 이상치, 중복 확인

### Step 2. 실패 구간 분석

- 어떤 시간대, 어떤 종목, 어떤 이벤트에서 실패했는지 확인

### Step 3. 특징 개선

- 가격 특징 추가
- 이벤트 특징 추가
- 심리 프록시 추가

### Step 4. 모델 개선

- 하이퍼파라미터 조정
- 앙상블
- 확률 보정

### Step 5. 재검증

- 같은 기간이 아닌 새로운 워크포워드 구간에서 재평가

### Step 6. 챔피언/챌린저 비교

- 운영 모델과 후보 모델을 나란히 평가

## 8. 운영 중 성능 모니터링

실시간 운영에서는 오프라인 성능만으로 충분하지 않습니다.

반드시 추적할 항목:

- 최근 1일, 1주, 1개월 성능
- 종목군별 성능
- 이벤트 유형별 성능
- 고확신 예측의 실제 적중률
- confidence calibration 변화

## 9. 성능 저하 원인 후보

1. 장세 변화
2. 특정 테마 과열/붕괴
3. 데이터 지연
4. 텍스트 소스 노이즈 증가
5. 종목군 분포 변화

## 10. 모델 교체 원칙

새 모델은 아래 조건을 만족할 때만 교체합니다.

1. 핵심 테스트 구간에서 기존 모델보다 우위
2. 특정 소수 구간만 잘하는 과적합 패턴이 없음
3. calibration이 나빠지지 않음
4. 실시간 추론 지연이 허용 범위 내

## 11. 장기적으로 고려할 고도화

- 장세 레짐 분류 후 조건부 모델 선택
- 종목군/테마군별 특화 모델
- 텍스트 인코더 고도화
- order book sequence model
- 설명 가능성 리포트 자동 생성
