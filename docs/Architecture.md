# 아키텍처

## 역할

이 문서는 전체 시스템의 큰 흐름을 설명하는 참고 문서다.

## 현재 구조

1. `brokers`: KIS 인증, REST 조회, WebSocket 연결
2. `collectors`: 외부 응답을 내부 이벤트 형식으로 변환
3. `storage`: JSONL과 SQLite에 원시 데이터, 가공 데이터, 서빙 데이터를 기록
4. `features`, `labels`: 분봉, 특징 스냅샷, 라벨 생성
5. `models`: 기준 모델, centroid 모델, 모델 registry, loader
6. `services`: 연구, 실시간 처리, 리포트, 오케스트레이션
7. `paper_trading`, `portfolio`, `risk`: 신호, 포지션, 리스크 게이트, 모의운용 상태 관리

## 기본 데이터 흐름

`KIS -> 원시 체결/호가 -> 분봉 -> 특징/라벨 -> 학습/백테스트 -> 실시간 예측 -> 신호 -> 목표 포지션 -> 모의 주문/체결 -> 리포트`

## 현재 판단

- 구조 방향은 맞다.
- 지금은 설계를 더 늘리는 것보다 실제 실시간 검증과 모델 확장이 중요하다.
