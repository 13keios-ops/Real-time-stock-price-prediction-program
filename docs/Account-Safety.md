# Account Safety Plan

## 1. 목적

사용자는 이미 한국투자증권 `실전투자계좌용 API`와 `모의투자계좌용 API`를 모두 확보했습니다. 이 상태에서는 기능 구현보다 `오주문 방지`가 더 중요합니다.

이 문서는 실전/모의 계좌를 안전하게 분리하는 기준을 정의합니다.

## 2. 핵심 원칙

1. 기본 모드는 항상 `paper`
2. 실전 주문 기능은 기본값 `disabled`
3. 실전 API 키가 있어도 주문 로직은 연결하지 않음
4. 계좌 종류와 실행 모드는 코드와 설정 양쪽에서 이중 확인

### 현재 확정 선택안

- `paper/live 분리 + 기본값 paper + 실전 주문 기본 비활성화`를 현재 기준으로 채택합니다.

## 3. 초기 환경 분리

초기에는 최소 아래처럼 환경을 나누는 것이 좋습니다.

### 모의투자 설정

- `KIS_PAPER_APP_KEY`
- `KIS_PAPER_APP_SECRET`
- `KIS_PAPER_ACCOUNT_NO`
- `TRADING_MODE=paper`

### 실전투자 설정

- `KIS_LIVE_APP_KEY`
- `KIS_LIVE_APP_SECRET`
- `KIS_LIVE_ACCOUNT_NO`
- `TRADING_MODE=live`

중요:

- 개발 초기에는 `TRADING_MODE=live` 자체를 허용하지 않는 것이 좋습니다.

## 4. 코드 레벨 안전장치

아래 장치는 반드시 필요합니다.

### 1차 안전장치

- 주문 함수는 `paper` 모드에서만 실행
- `live` 모드면 예외 발생

### 2차 안전장치

- 모드와 계좌번호 prefix를 함께 검증
- 주문 전 계좌 타입 재확인

### 3차 안전장치

- `ENABLE_REAL_TRADING=true` 같은 별도 플래그 없이는 실전 주문 절대 금지

현재 프로젝트 단계에서는 이 3차 안전장치도 켜지지 않게 두는 것이 맞습니다.

## 5. 운영 레벨 안전장치

### UI/로그 표시

- 현재 모드를 항상 화면 상단에 크게 표시
- `PAPER MODE`와 `LIVE MODE`를 색상과 텍스트로 명확히 구분

### 프로세스 분리

- paper 전용 프로세스
- live 조회 전용 프로세스

### 데이터 분리

- paper 주문 로그와 live 계좌 조회 로그를 분리 저장

## 6. 비밀정보 관리 원칙

1. 키는 저장소에 절대 커밋하지 않음
2. `.env` 또는 별도 비밀 저장소 사용
3. paper와 live 키를 같은 파일에 섞지 않음
4. 로그에 app key, account number 전체를 남기지 않음

## 7. 개발 단계 권장 정책

### 현재 단계

- 실전 API: 계좌/잔고/주문 가능 인터페이스 확인용
- 모의 API: 실시간 검증 및 자동주문 테스트용

### 다음 단계

- paper 주문 엔진 완성
- risk event 로깅 추가
- 모의 성과 누적 확인

### 실전 전환 전 필수 조건

1. 충분한 기간의 모의투자 검증
2. 비용/슬리피지 보수 시나리오에서도 안정성 확인
3. 실전 주문 safety checklist 구현
4. 실전 모드 별도 승인 절차 마련

## 8. 긴급 중단 장치

초기 구현 때부터 아래를 준비하는 것이 좋습니다.

1. 전역 거래 중단 플래그
2. 일일 손실 초과 시 자동 중단
3. API 장애 시 자동 중단
4. 데이터 지연 시 자동 중단
5. 수동 킬스위치

## 9. 추천 구현 순서

1. paper 전용 주문 인터페이스
2. live 조회 전용 인터페이스
3. 공통 브로커 추상화
4. risk gate
5. 실전 모드 코드는 인터페이스만 남기고 미연결 유지

## 10. 현재 전체 기획에서 중요한 판단

실전 API를 이미 확보했더라도, 지금 프로젝트 단계의 목표는 `실전 집행`이 아니라 `예측 검증과 전략 안정화`입니다.

따라서 당분간은 다음 기준이 맞습니다.

- 자동 모의주문은 활성화
- 실전 주문은 비활성화
- 실전 API는 조회/준비용으로만 유지
